# memorize_hub 설계 기준 문서(Hub SoT)

> 전신 프로젝트의 기록이다. mori-nest의 현재 요구사항은 아니다.
> 2026-09-24에 안내 문구를 한국어로 정리했으며, 기존 결정과 문서 식별자는 유지했다.

memorize_hub의 전송 중계와 제어 평면 관문을 지탱하는 아키텍처 불변 조건과 확정된 결정들이다.
`memorize/docs/SoT`의 제품 설계와 짝을 이루며, 그 문서에서 다루지 않는 **Hub의 구현·아키텍처**를 담는다.
확정된 내용은 개별 문서에, 미결 내용은 `H900-open-decisions.md`에 있다.

## memorize 설계 문서와의 관계

- memorize 문서는 정체성·동기화·공유·보안의 제품 요구사항을 다룬다.
  Hub 문서는 전송 구조·제어 평면 스키마·인가 계층·배포로 그 요구사항을 실현하는 방법을 다룬다.
- Hub 문서는 `memorize SoT-040`처럼 제품 문서를 인용하지만 대체하지 않는다.
  제품 결정을 바꿀 때는 memorize 저장소에서 대체 관계를 기록한다.
- 두 평면의 경계, `wsp_` 전송 구조, 제어 평면 스키마 등 Hub 고유의 아키텍처는 이 문서 묶음이 기준이다.
  이 기준은 전신 프로젝트 당시의 것이며 mori-nest에 자동으로 적용되지 않는다.

## 상태 범례

- **불변(Invariant):** 내용을 해석하지 않는 중계, 불투명한 추가 전용 로그, 두 평면의 분리가 강제하는 조건이다.
  바꾸려면 모델 자체를 바꿔야 한다.
- **결정(Decision):** 의도적으로 선택한 사항이며 명시적으로 대체되기 전까지 유효하다.
- **미결(Open):** 아직 정하지 않은 사항이다. 확정된 내용으로 오해하지 않도록 `H900`에 둔다.

## 기록 규율

memorize 문서와 같은 ‘추가하고 대체하기’ 원칙을 따른다.
확정된 문서를 제자리에서 덮어쓰지 않는다. 불변 조건이나 결정을 바꿀 때에는
대체 문서를 추가하고 이전 문서에 `대체됨:`을 남긴다.

## 목표로 삼은 정상 사용 흐름

- **HP1 — 여러 프로젝트의 기억 공유:** 여러 저장소의 로컬 `memorize.db`를 한 작업공간에
  합집합으로 통합한다. 어느 저장소의 세션에서도 출처 표시와 함께 서로의 기억을 본다.
- **HP2 — 서로 다른 계정의 합류와 병합:** 기기·폴더·사용자가 달라도 같은 작업공간에
  합류한다. 생성 → 초대 → 폴더 지정 → 동기화 순서로 진행하며, 로컬 정체성을 유지한 채
  데이터베이스 전체를 합집합으로 통합한다.

두 흐름 모두 로컬에 전체 복제본을 두고 Hub를 전송 경로로 사용한다.
서버 측 증류, 종단 간 암호화, 실시간 처리는 사용하지 않는다(`H060`, `H070`, `H900` 참고).
상세 구조는 `H020`, `H040`에 있다.
